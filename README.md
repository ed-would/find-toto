## Открыть подарок на компьютере

1. **Распакуй архив целиком.**
2. Открой `START-HERE.html` двойным кликом.
3. Нажми **«Проверить все 13 остановок»**, если сначала хочешь всё посмотреть сам.

Можно сразу открыть `index.html`. Ничего устанавливать или собирать для такого запуска не нужно. Все игровые изображения, стили, код и звуки находятся в проекте; звук синтезируется в браузере и включается отдельной кнопкой.

Для Рины лучше использовать опубликованную ссылку GitHub Pages: так сохранение привязано к постоянному адресу сайта. В режиме `file://` правила хранения могут отличаться между браузерами. Если сохранение недоступно, игра покажет об этом сообщение.

## Как Тото растягивает праздник на весь день

Отсчёт начинается **при первом открытии обычной страницы игры в этом браузере**, ещё на интро. Он не ждёт нажатия «Пойдём искать».

| Остановка | Когда откроется | Место |
| --- | --- | --- |
| 01 | Сразу | Городок маленьких чудес · осень |
| 02 | + 30 минут | Киото · сакура |
| 03 | + 1 час | Портленд · дождливый книжный |
| 04 | + 1 час 30 минут | Тбилиси · балконы и дворики |
| 05 | + 2 часа | Хабаровск · зимний Амур |
| 06 | + 2 часа 30 минут | Лиссабон · солнечные трамваи |
| 07 | + 3 часа | Сеул · вечерние фонарики |
| 08 | + 3 часа 30 минут | Амстердам · цветочный канал |
| 09 | + 4 часа | Ла-Лагуна · сиеста на Тенерифе |
| 10 | + 4 часа 30 минут | Кратер-Лейк · лесной лагерь |
| 11 | + 5 часов | Рейкьявик · северное сияние |
| 12 | + 5 часов 30 минут | Париж · мастерская под крышей |
| 13 | + 6 часов | Москва · праздничный осенний вечер |

Например, если Рина впервые зайдёт в 10:00, второй уровень откроется в 10:30, четвёртый — в 11:30, последний — в 16:00.

- Вкладку можно закрыть. При возвращении игра пересчитает доступные уровни по сохранённому времени начала.
- Открытия **не зависят от побед**. Можно прийти через полтора часа и сыграть сразу в первые четыре места, в любом порядке.
- Найденные уровни можно проходить снова сколько угодно. Повтор не сбрасывает общий отсчёт.
- Для главного письма нужно найти Тото на **всех 13 разных картинках**.
- После шести часов всё остаётся открытым. Игра не исчезает ночью и не имеет срока прохождения.
- Прогресс хранится локально в этом браузере. Другой браузер, устройство или удаление данных сайта начнут своё путешествие. Аккаунт, сервер и синхронизация между устройствами не используются.
- Твоё тестирование на своём компьютере не запускает расписание в браузере Рины.

Это дружеская праздничная игра. Расписание опирается на часы устройства, а не на серверную защиту от изменения времени.

## Проверить всё, не ожидая шесть часов

Добавь к адресу игры:

```text
?preview=1
```

Например, локально через сервер это будет `http://localhost:4173/?preview=1`. На GitHub Pages — обычная ссылка на игру с этим окончанием.

В этом режиме:

- открыты все 13 уровней;
- есть кнопка **«Проверить открытку этого уровня»**;
- можно открыть главное письмо из меню маршрута;
- обычное сохранение не читается и не меняется;
- после обновления страницы тестовые находки исчезнут.

Для прямого просмотра большого финала:

```text
?preview=1&final=1
```

**Рине отправляй обычную ссылку, без `preview` и `final`.** Не открывай её заранее в том браузере, в котором она будет играть: обычная ссылка сразу запоминает начало праздника.

## GitHub Pages — настоящая ссылка на подарок

Проект уже готов к публикации. В нём нет ключей API, базы данных, платных сервисов и npm-зависимостей. Все пути относительные, поэтому подходит адрес вида `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

### Через сайт GitHub

1. Создай новый репозиторий, например **`find-toto-for-rina`**. Для GitHub Free выбирай **Public**. Не создавай автоматически README, .gitignore или лицензию: нужные файлы уже лежат в архиве.
2. Загрузи в репозиторий **содержимое** папки `find-toto-13`. Файл `index.html` должен лежать прямо в корне репозитория, рядом с `assets`, `game.js` и `README.md`.
3. Убедись, что загрузилась папка **`.github/workflows/`** с файлом `pages.yml`. В некоторых файловых менеджерах папки с точкой скрыты; включи показ скрытых файлов при выборе. Не загружай ZIP вместо содержимого.
4. Открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Открой вкладку **Actions**, выбери **A little birthday magic**, нажми **Run workflow** для ветки **main**.
6. Когда задача **Send Toto to GitHub Pages** завершится успешно, ссылка появится в результате deployment и в **Settings → Pages**.
7. Проверь адрес с `?preview=1`, а Рине отправь тот же адрес **без параметров**.

При первой загрузке файлов автоматический запуск может начаться раньше включения Pages. После шага 4 просто запусти workflow вручную ещё раз. Следующие изменения в `main` проверяются и публикуются автоматически.

Если загружаешь через веб-интерфейс несколькими порциями, дождись загрузки всех папок и только потом запускай итоговую публикацию.

### Если удобнее через Git

Создай пустой репозиторий на GitHub. Открой терминал **внутри распакованной папки проекта**:

```bash
git init
git add .
git commit -m "A birthday adventure for Rina and Toto"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/find-toto-for-rina.git
git push -u origin main
```

Подставь свой логин и имя репозитория, затем выполни шаги 4–7 выше. Архив содержит файлы репозитория; локальная база `.git` создаётся командой `git init`.

В Actions запускаются проверки, копируется готовая игра в `dist/` и публикуется эта папка. Исходники проверок и инструкция в развёрнутую игру не попадают.

Официальная инструкция GitHub: [настройка источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) и [публикация через собственный workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Управление

| Действие | Компьютер | Телефон / планшет |
| --- | --- | --- |
| Приблизить / отдалить | Колёсико, кнопки + / − | Развести / свести два пальца |
| Перемещаться | Зажать и тянуть картинку | Перетаскивать одним пальцем |
| Найти Тото | Нажать на мордочку или видимую часть | Коснуться Тото |
| Показать всё | Кнопка рамки, клавиша 0 | Кнопка рамки |
| Картинка на весь экран | Кнопка в верхнем правом углу | Та же кнопка |
| Выйти из полного экрана | Та же кнопка или Esc | Та же кнопка |
| Выбрать уровень | «Наш маршрут» | Кнопка с лапкой в шапке |

На клавиатуре можно фокусироваться на картинке, перемещать её стрелками, менять масштаб + / − и нажать Enter или пробел, когда Тото окажется в центральном прицеле.

Fullscreen разворачивает **только картинку и её управление**. Если браузер не поддерживает системный fullscreen, изображение занимает всё окно вкладки.

Подсказки 1 и 2 дают только словесное направление. Подсказка 3 показывает большой ненавязчивый круг. Промахи ничем не наказываются.

## Изображения и разрешение

В проекте **13 разных игровых иллюстраций, 13 разных открыток и отдельная финальная иллюстрация**. Первое место заново создано с сохранением исходной композиции и исправленным Тото. Остальные меняют город, сезон, пространство и способ прятаться.

Основные изображения экспортированы в **3840 × 2560** в формате WebP. Это увеличение в **2,5 раза по каждой стороне** относительно исходных 1536 × 1024. Картинки в игре и координаты попаданий используют один и тот же размер.

Нативные результаты доступного генератора — 1536 × 1024. Экспорт в 3840 × 2560 сделан качественным ресемплингом; он **не добавляет новых нарисованных деталей** и не называется здесь нативной 4K-генерацией. Маленькие превью маршрута и портрет загружаются отдельно, чтобы не тянуть все большие картинки при входе.

Подробности и происхождение — в [ASSETS.md](ASSETS.md); творческие промпты — в [ART-PROMPTS.md](ART-PROMPTS.md). Последний файл раскрывает укрытия Тото.

## Для спокойного запуска через локальный сервер

Если Node.js 18+ уже установлен:

```bash
npm start
```

Открой `http://localhost:4173`. Остановить сервер — Ctrl+C. Установка пакетов не требуется.

Проверки и сборка:

```bash
npm run check
npm run build
```

- `npm run check` проверяет файлы, настоящие размеры WebP, координаты, подсказки, отсутствие внешних ресурсов и игровые сценарии.
- `npm test` запускает только сценарии игры и сохранения.
- `npm run build` собирает `dist/` для любого статического хостинга.
- `npm ci` допустима для привычного процесса работы, но устанавливать здесь нечего.

Результаты проведённых проверок и их границы — в [VERIFY.md](VERIFY.md).
